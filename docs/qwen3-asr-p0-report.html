短句能实时显示，整段重复解码方案未通过 P0

Qwen3-ASR 已在真实 Android 手机 CPU 上运行，并经测试 IME 更新宿主 composing。当前整段前缀反复解码路线在长句延迟、内存与上下文容量上有明确限制，不能据此进入生产功能开发。

1. 决策结论

P0 未通过，本轮尚未确认可发布的通用时长上限。3 秒快速中文样本达到热模型延迟目标；8 秒样本的最终等待已超过 2 秒目标。更长音频继续恶化，60 秒输入发生裁切并返回无效内容。默认配置内存超预算；低内存配置尚不能同时满足速度目标。
  • 模型选择保持 Qwen3-ASR；本轮失败针对固定 ONNX 导出、CPU 配置和整段重复解码路线，不代表所有 Qwen3-ASR 端内实现均不可行。
  • 已验证的短句能力不等于已验证“所有 3 秒语音可发布”，也不能把 8 秒直接设为通用保护上限；语速、语言、停顿和生成 token 数都会改变耗时。
  • 先评估有界音频分段 / 重叠窗口、上下文重导出与内存配置，再重新过 P0。暂不接入生产长按动作、录音权限设置和 Fcitx composing 所有权。

2. 设备、模型与实验条件

  • 真机 NX888J，系统报告 SoC SM8850，Android 16 / API 36，arm64-v8a，4 KB 页；系统 MemTotal 11,330,448 KiB。USB 连接并充电，测试 APK 前台可见。
  • sherpa-onnx v2.0.1 原始 AAR，CPU；默认 3 线程起测，再比较 2 / 3 / 4 线程。后续主要用 2 线程，样本比较不构成显著性证明。
  • Qwen3-ASR-0.6B INT8，导出版本 2026-03-25；维护者模型仓库 revision 68818b2313fe77bd06f6a7c5068ff3ef59d02b8a。模型与 tokenizer 共 987,015,347 字节（约 941 MiB）。主 ONNX 文件已在设备端 SHA-256 复核。
  • maxTotalLen=512，maxNewTokens=256；相同模型复用，各 run 新启进程。进程首次加载约 2.64–3.70 秒；未清空 Android 页缓存，不能称为首次安装冷盘加载。
  • 独立 Debug APK；native 推理为真实预编译库。测得的是测试进程总 PSS / RSS；生产 Fcitx 的额外常驻内存未包含。没有做 Release/R8 或 16 KB 设备运行测试；AAR 四个 arm64 .so 的 LOAD 段静态对齐为 0x4000。

系统 InputConnection 返回值和宿主 TextWatcher 均有记录；本轮有效流式实验的 composing span / 写入检查：均观察到宿主 composing，未记录写入失败。测试 IME 只承担 P0 通路，不是最终键盘界面。

5. 真实麦克风路径

使用可见 InputMethodService 中的 AudioRecord（VOICE_RECOGNITION、16 kHz、单声道、PCM16），手机扬声器播放已知公开测试语音并由麦克风声学回采；未保存原始麦克风录音。第一轮 mic-fast8-t2 使用原媒体音量 2/15，RMS 约 0.0003，转写与刺激内容不符，该组不作为有效听写质量证据。第二轮 mic-loud8-t2 将测试音量临时升至 8/15，结束后恢复原值；确认输出路由为内置扬声器、输入为内置麦克风。采集停止相对定时截止的最大偏差为 25.7 ms。

这验证了录音权限、采样、在推理进行中独立停止录音，以及系统 IC composing 路径。不是人现场口述；没有完成不同距离、蓝牙耳机、真实按住 / 抬手手势及尾字完整性验证。P0 的停止由定时截止模拟，最终等待包含在途 partial 和最后一次完整解码。

6. 内存、释放与稳定性

基线测试峰值 PSS 从约 2.1 GiB 随时长上升；全部有效实验中最高采样 PSS 为 4478 MiB。相对 45–60 MiB 左右的测试进程基线，明显超过暂定 1.5 GiB 增量预算。PSS 为每秒及关键阶段采样值，可能漏掉尖峰；RSS 高水位来自内核 VmHWM。

30 次同模型连续 8 秒解码：中位数 2.09 秒，峰值 PSS 2286 MiB，释放并 GC 后 964 MiB。

默认配置 release + GC 后约 2 秒仍可能有约 1 GiB 驻留，稍后的系统 meminfo 已明显回落。它不是确定的长期常驻，更不能仅凭两秒快照断言泄漏；尚未进一步归因到具体分配器或后台清理机制。

8. 可支持时长：本轮能确认什么

  • 3 秒：选定快速中文在热模型下能持续 composing，延迟样本达标；该默认配置的整体内存门槛仍未通过。
  • 5 秒：补测的 3 次快速中文 final 等待均超过 2 秒目标；不支持把“3 秒通过”线性外推到稍长语句。
  • 8 秒：有持续文字，但快速中文最终等待超标；不能宣称“8 秒内都实时”。
  • 15 秒：可解码中文，但单次完整解码已约 3.3 秒，持续刷新和 final 无法稳定达到目标。
  • 30 秒：能够输出英文；本轮没有完整人工词级对齐，不能仅凭返回文本证明首尾完整。
  • 60 秒：确认不支持当前整段配置的完整转写。运行时日志直接报告裁切，三次 offline 最终仅得到 language。

该导出图的实际 model limit 为 512；音频 token 与生成文本共享序列空间。上调 Kotlin maxTotalLen 不能突破导出图上限。即使输入音频尚未裁切，也须为语言前缀和输出留空间；因此不能把裁切开始位置推算成安全产品时长。

使用同一 3 秒零音频及固定 seed 的白噪声各重复 20 次。这是基础稳定性检查，不等价于 20 种真实噪声场景，也没有证明语音存在性过滤已完成；不能用“非空”指标替代正确文字或人工准确率。

  1. 保留 Qwen3-ASR，优先对 2 / 4 / 6 / 8 秒候选音频窗口或自然语音分段做延迟、接缝准确率、重复 / 漏字对比；全会话仍维持一段 composing。窗口数值作为实验档位，不能直接固化为用户录音上限。
  2. 结合内存配置对照，决定是否需要自定义运行时 / 独立私有推理进程。独立进程可以隔离崩溃和回收，但不能降低推理本身峰值，不能当作内存预算已解决。
  3. 如需更长上下文，重新导出 decoder 并锁定量化和 tokenizer；重新测移动端内存与质量，不直接替换现有制品。
  4. 通过修订后的 P0 后再推进 P1。当前未做 100 句 CER/WER、真实口述、多语言完整验收、Release/R8、16 KB 运行、生产 Fcitx 并发 composing 协议与所有生命周期竞态测试。
