更新检查与外部下载跳转

Fcitx5 for Android · 2026-10-29 · Spec v2

目标：用户在“关于”页主动检查更新；发现更高版本时展示版本信息，点击“前往下载”交给系统打开下载链接。首版不实现应用内下载、安装或后台自动检查。

1. 范围与默认决策

  • 在“关于 → 版本”分类新增“检查更新”，保留现有版本、Git Hash 和构建时间信息。
  • 仅点击后发起一次请求；应用启动、输入法启用和键盘输入过程均不触发网络访问。无定时任务、通知、更新忽略记录或结果缓存。
  • 成功且服务端 versionCode 大于本地实际安装版本号时，显示更新弹窗；否则提示“当前已是最新版本”。服务端版本较低也不提供降级入口。
  • 点击“前往下载”后通过 ACTION_VIEW 打开服务返回的绝对 HTTP/HTTPS 链接，由系统或浏览器处理；不申请存储或安装未知应用权限。
  • 正式版与 Debug 构建均支持更新检查，使用独立的软件内部名：正式版为 fcitx5-android，调试版为 fcitx5-android-debug。按构建类型选择对应序列，不跨序列回退。

3. 接口约定

采用引用聊天“查找软件更新接口”中已实现的 API，当前服务源码和接入文档均已核对。服务域名为 zp.ntutn.top。

GET https://zp.ntutn.top/api/v1/updates
    ?software=fcitx5-android
    &os=Android
    &arch=ARM64
    &packageType=apk
Accept: application/json
参数首版取值
software正式版使用 fcitx5-android，Debug 使用 fcitx5-android-debug，集中定义并按构建类型选择。此处为软件内部名，不是展示名，也不是自动取 applicationId。
osAndroid，区分大小写。
arch已安装 APK 为 arm64-v8a 时使用 ARM64；为 x86_64 时使用 X86_64。
packageTypeapk，固定查询，不回退到其他类型。

不传当前版本号：接口只查询最新包，版本比较在客户端完成。按完整四元组精确查询；200 响应中 items 非空时，始终选择服务端返回顺序中的第一项（items[0]），多项结果不视为错误，不重新排序或寻找更高版本。校验第一项的 software、os、arch、packageType 与请求一致后，再解析版本并比较；第一项无效时提示失败，不尝试后续项。空数组视为无效响应。

4. 版本、架构与发布一致性

  • 比较依据：从 PackageManager 获取当前安装包的 longVersionCode（兼容旧 Android 的 versionCode），将服务端 versionCode 严格解析为正 Long 后比较。不能使用 versionName、字符串顺序或 BuildConfig 默认版本号比较。
  • 原因：项目按 ABI 修改 APK 的 versionCode，当前规则为 baseVersionCode × 10 + ABI ID，ARM64 的 ID 为 2，X86_64 的 ID 为 4。当前 baseVersionCode 为 11，分别对应 112、114；发布时必须填写 APK 的实际值。
  • 架构识别：基于当前安装的 native 库 ABI 判断，不单凭设备首选 ABI。无法可靠确定时提示“不支持此安装包的更新检查”，不猜测架构。
  • 32 位边界：仓库支持 armeabi-v7a / x86，但服务当前仅支持 ARM64 / X86_64。32 位安装包提示“更新服务暂不支持此架构”，不请求 64 位包，也不自动迁移架构。
  • 发布约束：同一更新序列保持相同包名与签名，递增实际 versionCode。正式版序列发布正式包，Debug 序列发布调试包；两个软件内部名分别维护版本和下载链接，比较各自安装包的实际 versionCode。客户端首版不下载 APK，因此不能预先验证远端签名；发布方负责链接与包的一致性。

5. 错误与网络处理

情况用户提示 / 行为
404 SOFTWARE_NOT_FOUND“更新服务尚未配置此软件”，不能当作无更新。
404 NO_MATCHING_PACKAGE“暂无适用于此架构的更新包”。
409 AMBIGUOUS_LATEST“更新信息存在冲突，请稍后重试”，不选择下载地址。
400、429、5xx、其他 HTTP 错误“检查更新失败，请稍后重试”；可附 HTTP 状态码，不自动重试。
无网络、DNS/TLS 错误、超时“无法连接更新服务，请检查网络后重试”。
非 JSON、空结果，或第一项缺失必需字段、版本溢出、维度不匹配“更新信息无效，请稍后重试”。允许未来扩展字段。
非法下载链接只接受有主机名的绝对 HTTP/HTTPS 地址，拒绝 file、intent、javascript 等 scheme；不提供跳转按钮。
系统没有可打开链接的应用捕获 ActivityNotFoundException，提示“没有可打开下载链接的应用”，保留当前页面。

使用 HTTPS 请求元数据；连接和读取各设置 10 秒超时、响应体大小上限 64 KiB，拒绝接口重定向。取消检查不显示失败提示。进入下载链接后由外部应用处理后续跳转和下载。

7. 验收标准

  1. 打开关于页不发请求；点击后一次只允许一个检查，UI 可操作。
  2. 同架构高版本弹窗；相等或较低版本均不提供更新按钮。测试 9 → 10、64 位大整数与溢出，验证数值比较。
  3. “前往下载”只触发系统外部链接打开；取消不跳转。应用内不出现下载进度、安装流程或相关权限请求。
  4. 模拟 ARM64 / X86_64，确认完整查询参数和实际安装版本号；32 位 / 未识别 ABI 不请求更新。分别验证正式版与 Debug 使用各自的软件内部名、比较各自安装版本，并跳转各自下载链接；任一序列无发布记录时不回退到另一序列。
  5. 覆盖多项结果：只使用第一项，即使后续项版本更高也不改选；第一项无效时失败，不使用后续项。覆盖 404 两类错误、409、503、超时、非法 JSON、错架构、空结果和危险 URL；均不误报最新版。
  6. 页面退出、旋转与重复点击不导致重复弹窗、已销毁窗口访问或卡住入口；无浏览器时可正确提示。
  7. 执行相关单元测试、Android 编译；正式版和 Debug 发布数据可用后，分别用对应的实际签名 APK 完成“检查 → 发现新版 → 外部打开链接”真机验证。

8. 当前证据与待落实条件

已核实（2026-10-29）：线上 API 能返回 JSON 错误；查询 software=fcitx5-android&os=Android&packageType=apk 返回 HTTP 404 / SOFTWARE_NOT_FOUND，Android 下载列表显示 0 次分发。因此，目前不能验证真实新版的成功路径。

后台分别使用 fcitx5-android（正式版）和 fcitx5-android-debug（调试版）两个软件内部名，包类型均为 apk。上线前需创建两条软件记录，分别配置对应架构、实际 APK versionCode、版本名和下载链接。开发期间已复核两个内部名的 ARM64/apk 精确查询，均返回 SOFTWARE_NOT_FOUND。若已有约定内部名，应替换对应常量。本次不修改更新服务或发布数据。
